# 第二部分:ikun社区 · 完整项目文档

## 一、项目概述

| 项目 | 内容 |
|:---|:---|
| **名称** | ikun社区 |
| **Slogan** | 天下ikun是一家 |
| **定位** | 粉丝社区 · 宗门制成长体系 |
| **首期形态** | 移动端网页Demo(Vue 3) |
| **后续形态** | 微信小程序 |
| **核心特色** | 宗门等级 + 身份证编号 + 坤系头像 + 打卡成长 |

## 二、等级与身份体系

### 弟子阶段(Lv1-Lv4)

| 等级 | 称号 | 打卡天数 | 贡献值 | 加精帖数 | 图标状态 |
|:---:|:---|:---:|:---:|:---:|:---|
| Lv1 | 外门弟子 | ≥10 | — | — | 点亮 **i** |
| Lv2 | 内门弟子 | ≥20 | ≥10 | — | 点亮 **i,k** |
| Lv3 | 核心弟子 | ≥30 | ≥30 | — | 点亮 **i,k,u** |
| Lv4 | 亲传弟子 | ≥40 | ≥50 | ≥1 | 点亮 **i,k,u,n** |

### 长老阶段(Lv5,内部细分)

| 子阶 | 称号 | 条件 | 身份要求 | 边框 | 后台权限 |
|:---:|:---|:---|:---|:---|:---:|
| 5.1 | 外门长老 | 打卡≥50+贡献≥50+加精≥2 | 非管理员 | 青灰环 | ❌ |
| 5.2 | 内门长老 | 外门长老+贡献≥80 | 非管理员 | 银白环 | ❌ |
| 5.3 | 客卿长老 | 内门长老+贡献≥100 | 非管理员 | 碧蓝环+羽扇 | ❌ |
| 5.4 | 核心长老 | 达外门长老条件+被任命 | ✅ 管理员 | 紫金环+盾牌 | ✅ |
| 5.5 | **大长老** | **系统保留(ID=1)** | 你本人 | 炫彩旋转环+王冠 | 全部 |
| 5.6 | 宗主 | **占位(ID=0)** | 预留 | 不展示 | — |

### 权力结构图

```text
宗主(ID=0)· 占位 · 不可达
      ↓ 预留
大长老(ID=1)· 你 · 最高实权
      ↓ 任命
核心长老(管理员)· 有后台权限
      ↓ 自然晋升
客卿长老 → 内门长老 → 外门长老
      ↓ 量化晋升
亲传弟子 → 核心弟子 → 内门 → 外门
```

## 十二、核心交互流程

### 流程1:新用户注册→获得身份证

```text
登录成功 → 判断是否首次 → 是 → 选择工种头像 → 播放翻转动画 → 显示身份证 → 可截图
                        → 否 → 直接进入首页
```

### 流程2:打卡→升级判定

```text
用户点击打卡 → 检查今日是否已打卡
  → 已打卡 → 提示
  → 未打卡 → 记录打卡 → +5贡献值 → 触发等级检查
    → 满足升级 → 更新等级+称号 → 自动解锁新边框 → 推送通知
    → 不满足 → 刷新日历
```

### 流程3:管理员删帖→审批

```text
审核员点击删帖 → 帖子热度>100?
  → 否 → 直接删除
  → 是 → 提交审批 → 大长老收到通知 → 批准/驳回
```

### 流程4:核心长老任命

```text
大长老在后台 → 用户列表 → 选择用户 → 点击「任命为核心长老」
  → 检查是否达到Lv5条件
    → 是 → 写入admins表 → 用户角色变为核心长老
    → 否 → 提示未达条件
```
